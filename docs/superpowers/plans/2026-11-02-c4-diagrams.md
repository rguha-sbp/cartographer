# C4 Diagrams Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `cartographer` draws a full, notation-correct C4 set (Context, Container, Component, optional Code, Deployment, Dynamic) for one software system as draw.io files, from one verified model that Claude curates from the repo or the engineer's answers.

**Architecture:** Claude writes one C4 model (`model.json`, cache folder, never committed). A C4 verifier checks structure, evidence and completeness against the Terraform facts. Pure projection functions turn the model into one curated-shaped dict per view, which the existing layout, routing, checks and renderer draw; a `Notation` object (AWS or C4) supplies legend and line colours, and C4 box/group kinds get their own styles. Every run overwrites the views and deletes view files the model no longer produces.

**Tech Stack:** Python 3.13, stdlib only (plus the existing `python-hcl2`), pytest, ruff, `uv run`.

**Spec:** `docs/superpowers/specs/2026-11-02-c4-diagrams-design.md`

## Global Constraints

- No new runtime dependency; the tool never calls an LLM.
- Every module under 300 lines (`tf_extract.py` is already over: do not grow it).
- TDD: every task starts with a failing test.
- Plain ASCII in user-facing text: no em dashes, en dashes or smart quotes.
- Existing L7 output stays byte-identical: `tests/test_layout.py`, `tests/test_drawio_format.py` and every other existing test pass unchanged, except the two index/snapshot tests Task 7 and Task 8 rewrite on purpose.
- Text at least 12 px; open arrowheads for relationships; no animation, shadow, gradient, 3D or sketch styles.
- C4 palette: person `#08427B`, software system `#1168BD`, container `#438DD5`, component `#85BBF0`, external `#999999`; boundaries dashed, unfilled; relationship lines one neutral colour `#707070`.
- Work only in the worktree on branch `feat/c4-diagrams`; commit per task; never push to `main`.
- Run tests with `uv run pytest -q` and lint with `uv run ruff check src tests` from the worktree root.

## Review Focus

1. A model with two relationships between the same pair of visible elements, different labels and no shared `summary`: the build fails and names both relationship ids (Task 1 test `test_rollup_conflict_names_both_relationships`).
2. A rerun after a container was removed: its `-3-component-<id>` files are deleted, and an unrelated L7 diagram in the same folder (`gip.drawio`) survives (Task 7 test `test_build_deletes_stale_views_only_of_this_model`).
3. A relationship between an element and its own ancestor, a parent cycle, or a duplicate id: verify reports it instead of crashing in the projection (Task 2 test `test_structure_errors_do_not_crash`).
4. A container with no components, or a model with no `code` elements: no Component or Code view is produced for it, and nothing fails (Task 4 test `test_views_skip_empty_levels`).
5. A relationship label or description containing a secret: verify fails with "looks like a secret" (Task 2 test `test_secret_in_text_fails`).

### Task 1: C4 model schema and model helpers

**Files:**
- Create: `src/cartographer/c4.schema.json`
- Create: `src/cartographer/c4_model.py`
- Test: `tests/test_c4_model.py`

**Interfaces:**
- Produces:
  - `Model = dict[str, Any]`
  - `SCHEMA: Path` (the schema file)
  - `class RollupError(Exception)` with `.pair: tuple[str, str]` and `.relationships: list[str]`
  - `elements(model) -> dict[str, dict]` (id -> element)
  - `in_scope(model) -> dict` (the single `system` element without `external: true`)
  - `ancestors(model, eid: str) -> list[str]` (nearest first)
  - `visible(model, eid: str, shown: set[str]) -> str | None` (eid or its nearest ancestor in `shown`)
  - `rollup(model, shown: set[str]) -> list[dict]`: edges `{"src", "dst", "label", "dashed"}` between shown elements, sorted by (src, dst)
  - `type_line(element: dict) -> str`
  - `edge_text(label: str, technology: str | None) -> str`

Schema (`c4.schema.json`, draft 2020-12, `additionalProperties: false` everywhere, evidence `$defs` identical to the three arms in `curated.schema.json`):
- top level required: `source` (`terraform | description`), `elements`, `relationships`; optional `deployment`, `scenarios`, `omitted` (`[{tf, reason (maxLength 80)}]`), `assumptions` (same as curated).
- element: required `id`, `type` (`person | system | container | component | code`), `name`, `description` (maxLength 120), `evidence` (minItems 1); optional `parent`, `external` (bool), `technology`, `shape` (`app | store | queue`), `stereotype` (`class | interface | enum | record | module`).
- relationship: required `id`, `src`, `dst`, `label` (maxLength 40), `dashed`, `evidence` (minItems 1); optional `technology` (maxLength 30), `summary` (maxLength 40), `kind` (`uses | inherits | implements`, Code level only, default `uses`).
- deployment: required `environment`, `nodes`, `instances`. Node: required `id`, `name`, `technology`, `evidence`; optional `parent`, `frame` (`cloud | region | account | vpc | subnet`), `tier` (`public | private | isolated`), `service` (AWS icon name), `tf` (addresses). Instance: `{container, node}`.
- scenario: required `id`, `name`, `steps` (relationship ids, minItems 1).

### Task 2: C4 verifier

**Files:**
- Create: `src/cartographer/c4_verify.py`
- Test: `tests/test_c4_verify.py`

**Interfaces:**
- Consumes: `c4_model.elements`, `ancestors`, `in_scope`; `verify_shared.code_hit`, `verify_shared.SECRET_REASON`; `secret_patterns.contains_secret`.
- Produces:
  - `COMPLETE_TYPES: tuple[str, ...]` = `aws_lambda_function, aws_ecs_service, aws_instance, aws_autoscaling_group, aws_db_instance, aws_rds_cluster, aws_dynamodb_table, aws_s3_bucket, aws_sqs_queue, aws_sns_topic, aws_kinesis_stream, aws_elasticache_cluster, aws_elasticache_replication_group`
  - `verify(model: Model, facts: dict | None, repo: Path) -> list[str]` (sorted errors, empty means pass; `facts` is None for `source: description`)
  - `stated_only(model: Model) -> list[str]`
  - `report(errors: list[str], stated: list[str]) -> str` (first line `C4 model: N problems` or `C4 model: ok`, then the stated-only section when non-empty)

Rules (each failing rule yields one error string starting with the item id):
- Structure: unique ids across elements, relationships, deployment nodes, scenarios; exactly one in-scope system; parent types `container -> system`, `component -> container`, `code -> component`, person and system have no parent; no parent cycles; containers and components have `technology`; relationship ends exist and are neither equal nor ancestor/descendant of each other; `kind` other than `uses` only between `code` elements; scenario steps name existing relationships; instance container and node exist; deployment node parents exist.
- Evidence: `fact` arm only when `facts` is given and the id exists; for a relationship the fact's src/dst must be among the `tf` of deployment nodes hosting the containers of its two ends (either direction). `file` arm checked with `code_hit`. `stated` arm is accepted everywhere, but a container, component or code element whose evidence is only `stated` is listed by `stated_only(model) -> list[str]` (ids, sorted) and printed by `report` under `Stated by the engineer, not found in the repo` (information, not an error), so the tech lead sees what rests on an answer; in `source: terraform`, deployment nodes need `tf` addresses that all exist in facts.
- Completeness (only with facts): every resource whose `type` is in `COMPLETE_TYPES` appears in some deployment node `tf` or in `omitted[].tf`; else `"<address>: not on any view and not omitted"`.
- Secrets: any element, relationship, deployment node or assumption where `contains_secret` is true -> `"<id>: looks like a secret"`.

### Task 4: Context, Container, Component and Dynamic projections

**Files:**
- Create: `src/cartographer/c4_views.py`
- Test: `tests/test_c4_views.py`

**Interfaces:**
- Consumes: `c4_model.*` (Task 1), `c4_styles.element_label`, `element_size` (Task 3).
- Produces:
  - `@dataclass(frozen=True) class View: slug: str; title: str; curated: dict`
  - `views(model: Model) -> list[View]` in this order: `1-context`, `2-container`, `3-component-<container id>` per container with components (container order), `4-code-<component id>` per component with `code` children (Task 6), `5-deployment` when `deployment` is present (Task 5), `6-dynamic-<scenario id>` per scenario.
  - Titles: `System Context diagram for {S}`, `Container diagram for {S}`, `Component diagram for {S}: {container}`, `Code diagram for {S}: {component}`, `Deployment diagram for {S}: {environment}`, `Dynamic diagram for {S}: {scenario}` (S = in-scope system name).
  - Each `curated` has `title`, `groups`, `nodes`, `externals`, `edges` in the shape `tf_layout` consumes (nodes: `service: "other"`, `tf: []`, `multi: False`, `group`, `box`, `c4`; externals: `icon: "none"`, `box`, `c4`; groups: `kind: "boundary"`, `parent: None`, `column: 0`, label `"{name}\n[Software System]"` or `"{name}\n[Container: tech]"`).

Content per view:
- Context: the in-scope system as a node (no group); persons and external systems that have a rolled-up relationship to it as externals. Edges `rollup(model, shown)`.
- Container: boundary group of the in-scope system holding its containers; persons and external systems connected to any container as externals.
- Component: boundary group of the container holding its components; connected persons, external systems and sibling containers as externals.
- Dynamic: the elements the scenario's relationships touch, shown at container level inside the system boundary (persons/external systems outside); edges are only the scenario steps, label `"{n}. {label}"`, in step order.
